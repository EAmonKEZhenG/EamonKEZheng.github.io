Cloud Deployment Choices Impacting Performance of a Web Application Using Microservices Architecture

Overview

This project evaluates how deployment topology and service coupling strategy affect the performance of a cloud-hosted online game backend. We designed and benchmarked a microservices system to measure latency and throughput trade-offs under realistic concurrent load.

System Design

The core backend used Nakama + Postgres for authentication, matchmaking, and realtime play sessions. Around this core, we built supporting services to separate control, ingestion, and observability concerns.

Microservices Architecture

  • Admin API: FastAPI control plane for health checks, gate checks, and client event submission.
  • EventHub: FastAPI + Postgres service for event ingestion and durable storage.
  • Dashboard: read-only aggregation service and UI for system status and experiment metrics.

Communication model:

  • Client to Nakama: HTTP login and WebSocket matchmaking/realtime.
  • Client to Admin: HTTP event submission or gate check.
  • Admin to EventHub: HTTP event forwarding.
  • Dashboard to upstream services: HTTP read paths.

Deployment Topologies

We compared three cloud deployment options:

  • Single VM
  • Multi-VM / Multi-Zone
  • Kubernetes

We also compared two coupling modes:

  • Synchronous: client waits for Admin gate check before matchmaking.
  • Asynchronous: client proceeds directly to Nakama without blocking.

Benchmark Methodology

  • Built preflight.py for liveness and full-pipeline readiness checks before load runs.
  • Built bench.py for repeatable load testing with concurrent virtual users.
  • Measured latency with mean, P95, and P99 metrics.
  • Measured throughput as successful operations per second.

Results

  • Asynchronous coupling consistently produced higher throughput and lower latency than synchronous coupling.
  • Single-VM deployment performed well at low load but saturated earlier as concurrency increased.
  • Multi-VM / Multi-Zone introduced cross-host and cross-zone overhead, worsening tail latency.
  • Kubernetes showed better sustained scaling behavior under higher concurrency.
  • Synchronous coupling lengthened the client critical path and reduced overall system throughput.

Lessons Learned

System performance was shaped as much by architecture and deployment choices as by service implementation. Designing for asynchronous paths, minimizing cross-zone hops, and benchmarking with clear tail-latency metrics were key to building a reliable and scalable microservices backend.
